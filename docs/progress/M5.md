# M5 · In-call photo references (REF-1..11)

**Built**
- iOS: own-mic Transcribe streaming (SigV4-presigned WebSocket + event-stream codec, no AWS SDK, D-5) with a Chime live-transcription fallback (D-202/D-106); suggestion chip (Ask first, 8 s), Automatic mode with 2 s Hide pill, Off; `PhotoShareSession` (offer/ready/end/cancel, 1.5 s ready fallback, per-sender queue max 5 with 6/4.5/3.5 s durations, server-timestamp ordering, echo suppression) and the pure display rule; spring cross-dissolve swap with "from <nickname>" label and queue dots; fling to cancel.
- Backend: transcript route → 60 s two-speaker context → Nova detector → Titan text embedding → S3 Vectors (speaker's library only, date/place filters, threshold 0.37) → `photo.suggestion`; shares with recipient-only 5-minute presigned GETs (D-6); audit log; stage latency metrics.

**Verification**
- Detector eval: precision 1.000, recall 0.896 on 140 cases (targets 0.85 / 0.60). Retrieval eval: top-1 1.00, top-3 1.00 on 60 CC0 photos — note the thin similarity margin (D-105); real camera rolls will be harder.
- Integration: REF-1..7/10/11 (transcript over WS → suggestion; Off mode; shares recipient-only).
- Latency (CloudWatch, `tools/latency-report/report.sh`): server pipeline p50 746 ms / p95 1034 ms (n=54). With ~700 ms for Transcribe finals that's ≈1.5 s / 1.8 s against the 2.5 s / 4 s targets.
- Peer bot `two-bots` over real Chime: single share on both ends then revert together; **Show → visible on both p50 346 ms / p95 384 ms** (target 800 ms); simultaneous share (each sees the other's); fallback after cancel; queue 6002 / 4502 / 6002 ms.
- iOS unit tests: display-rule truth table, protocol state machine (incl. the in-flight race found by the bot's tests), timing, codecs, SigV4 vectors.
- **E2E: the bot's offer reaches the real iOS app over Chime, the app downloads the share, replies `ready` (~250 ms), and its mini window shows the bot's photo "from Test Bot" — passing.** Fixed: photo overflowed the mini window (D-304).
- The app's own Transcribe WebSocket authenticated against AWS from the simulator (the service replied "no audio received"), confirming the hand-rolled SigV4 + Cognito identity path.
